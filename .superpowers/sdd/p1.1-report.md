# P1.1 Implementation Report

## Outcome

Portable skill fields now have one canonical source at `skill.frontmatter.schema.json#/$defs/core`. The canonical and Claude profiles compose that core with Draft 2020-12 `allOf`, reject unknown fields through `unevaluatedProperties: false`, and preserve their existing `allowed-tools` difference.

## Architecture

- Canonical `$defs/core` owns `name`, `description`, `license`, `compatibility`, `metadata`, and `allowed-tools`, including required `name` and `description`.
- Core exposes the shared `allowed-tools` string-or-array superset. The canonical profile narrows it to its existing string-only contract; the Claude profile inherits the superset and retains all existing Claude-only fields.
- The Claude schema references the canonical core by absolute `$id`; it does not duplicate the six shared property definitions.
- `schema-lib.mjs` registers schemas once by `$id`, accepts schema objects or paths, reuses validators by `$id`, and reports `unevaluatedProperties` with the existing unsupported-field diagnostic shape.
- Skill validation registers both generated profile schemas before either profile is compiled.
- The generated schema module and bundled CLI were regenerated.
