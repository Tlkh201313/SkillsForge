# R0.3 Implementation Report

## Outcome

Lockstep PASS reporting now depends only on collected version parity mismatches. Unrelated validation errors, including diagnostics containing `version `, still fail repository validation without suppressing a valid `version lockstep <expected>` entry in `passes`.

## Changes

- Collected lockstep mismatch diagnostics in dedicated `versionMismatches` state before appending them to `errors`.
- Added a regression fixture with an unrelated unsupported field named `version note` and asserted the failed overall result plus the lockstep PASS directly.
- Preserved existing validation exit semantics and mismatch diagnostic text.
